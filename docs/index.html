项目摘要 · 信用风险后训练

SFT 学到了有效风险排序，偏好优化暴露出明确的方法边界。

项目以 Qwen3.5-4B 和 German Credit 为主实验对象，系统比较 LoRA SFT、DPO/SimPO 与 Logistic Regression，并用无测试泄漏的成本敏感评测区分真实收益与标签先验偏移。

研究问题

后训练能否在强传统基线面前产生真实、稳定的风险判别价值？

  1. 指令模型能否从自然语言形式的表格记录中学习可泛化的风险排序？
  2. SFT 与 DPO/SimPO 改善的是条件判别能力，还是只改变标签先验？
  3. 失败根因来自数据、优化、阈值，还是目标函数与短标签任务的错配？

实施细节

可复现的数据、训练与评测实现

数据治理

German Credit 冻结为 700/100/200；通过 Schema、manifest、V1–V7 与 SHA-256 检查保证确定性。

LoRA SFT

Qwen3.5-4B 使用 response-only loss、LoRA r=16、alpha=32、dropout=0.05，训练 5 个 epoch、三个随机种子。

偏好优化

构造 Oracle、Hard 与多数据集 Preference，运行六组主 DPO/SimPO 实验及成本敏感对照。

无泄漏评测

统一计算 AUC、校准、召回、混淆矩阵与 Cost；阈值只从验证预测中选择。

实验结论

正向结果、诚实基线与方法边界

01

SFT ROC-AUC 提升 +0.232

SFT 是唯一持续产生有效风险排序的后训练方法。

02

LR 0.757 仍高于 SFT 0.747

项目声称接近，不声称稳定超越。

03

成本阈值有效但不能替代排序

验证集阈值降低 FN 成本，AUC 与校准指标防止伪改进。

04

6 / 6 组 DPO/SimPO 未超过 SFT

短标签偏好目标主要移动全局标签先验。

复现指引

先复现冻结指标，再按需运行完整 GPU 链路

CPU：复现最终指标

git clone https://github.com/UrgencyWu/risk-control-posttraining.git
cd risk-control-posttraining
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-eval.txt
python -m unittest discover -s tests -v
python -m src.evaluation.c7_final --output /tmp/c7.json

GPU：训练与推理

python -m pip install -r requirements-train.txt
export RISK_CONTROL_MODEL_ID=/path/to/Qwen3.5-4B
sbatch scripts/sft_slurm.sh
sbatch scripts/dpo_train.sh
sbatch scripts/simpo_train.sh
