项目摘要 · 信用风险后训练

SFT 学到了有效风险排序，偏好优化暴露出明确的方法边界。

研究问题

后训练能否在强传统基线面前产生真实、稳定的风险判别价值？

项目不只比较最终 Accuracy，而是同时检查样本级排序、概率质量、非对称成本和跨随机种子稳定性。

  1. 指令模型能否从自然语言形式的表格信用记录中学习可泛化的风险排序？
  2. LoRA SFT 与 DPO/SimPO 分别改变了样本判别能力，还是只改变了两个标签的整体概率？
  3. 当后训练失败时，根因是数据、优化、决策阈值，还是目标函数与二标签短回答任务的错配？

  6. 06偏好优化

  7. 07成本敏感决策

  8. 08最终评测与审计

    C7 统一指标与 log-probability 机制分析。

实验结论

正向结果、诚实基线与方法边界

项目保留成功结果、稳定性限制和机制性负结果，不以单次最佳指标替代完整证据。

SFT 有效

ROC-AUC 提升 +0.232

SFT 是唯一持续产生有效风险排序的后训练方法，并同步改善 PR-AUC、NLL 与 Brier。

诚实对比

0.757 仍高于 0.747

Logistic Regression 的排序与概率质量仍略强；最佳 SFT Cost 更低，但三随机种子均值不支持稳定超越。

决策规则

成本阈值有效，但不能替代排序

验证集阈值降低高风险漏判成本；AUC 与校准指标用于识别全部预测 high risk 的伪改进。

方法边界

6 / 6 组 DPO/SimPO 未超过 SFT

短标签偏好目标主要移动全局标签先验，未直接监督申请人之间的风险顺序，并多次导致单类别坍缩。

复现指引

先复现冻结指标，再按需运行完整 GPU 链路

公开指标可以完全由已提交的 valid/test 预测工件在 CPU 上重建；完整训练需要本地 Qwen3.5-4B 与 GPU 环境。

CPU：复现最终指标

不需要模型权重或 GPU。

git clone https://github.com/UrgencyWu/risk-control-posttraining.git
cd risk-control-posttraining
python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip -r requirements-eval.txt
python -m unittest discover -s tests -v
python -m src.evaluation.c7_final --output /tmp/c7_final_metrics.json
cmp outputs/c7_final_metrics.json /tmp/c7_final_metrics.json

GPU：训练与推理

需要本地模型路径、训练依赖和 Slurm 环境。

python -m pip install -r requirements-train.txt
export RISK_CONTROL_MODEL_ID=/absolute/path/to/Qwen3.5-4B
python -m src.baselines.logistic_regression
python -m src.baselines.qwen_zero_shot
sbatch scripts/sft_slurm.sh
sbatch scripts/dpo_train.sh
sbatch scripts/simpo_train.sh
